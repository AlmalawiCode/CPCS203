Q1
Primitive Data Types
Reading and updating a variable
int x = 5; x = x + 3; System.out.println(x);

Let us read this program the way we would work it out on the board — one statement at a time — and draw what the variable holds after each line.

Statement 1int x = 5;

This is a declaration together with an initialization. int x makes a variable called x. For a primitive type like int, the variable holds the actual value directly. The = 5 stores the value 5 inside it.

x
5
Statement 2x = x + 3;

This is an assignment. Java always works out the right-hand side first: it reads the current value inside x (which is 5), adds 3 to get 8, and then stores that result back into x, replacing the old value.

x
8
Statement 3System.out.println(x);

This prints the current content of x, which is now 8.

✅ The answer: 8
A primitive variable holds the value itself. We read the old value, compute, and store the new value back into the same variable.
Q2
Primitive Data Types
Integer division — where did the .5 go?
int a = 5; int b = 2; System.out.println(a / b);

Let us read this program one statement at a time.

Statement 1int a = 5;

Declaration and initialization of an int variable a holding the value 5.

a
5
Statement 2int b = 2;

A second int variable b holding the value 2.

b
2
Statement 3System.out.println(a / b);

Java computes a / b. Here is the key rule: when both sides are int, Java uses integer division — it keeps only the whole part and drops the fraction (it does not round).

So 5 ÷ 2 = 2.5, but the .5 is thrown away, and the result is 2.

✅ The answer: 2
int / int gives an int. 5 ÷ 2 = 2.5, but the .5 is dropped → 2.
⚠️ Very common mistake
Students expect 2.5. To actually get 2.5 at least one side must be a decimal: 5.0 / 2, or cast one side: (double) a / b.

Q4
Primitive Data Types
The famous double = 5 / 2 trap
double result = 5 / 2; System.out.println(result);

Let us read this program one statement at a time — the surprise is hidden in the first line.

Statement 1double result = 5 / 2;

Java always works out the right-hand side first, and only afterwards stores it into the variable. So there are two steps:

Step 1 — compute 5 / 2. Both 5 and 2 are int values, so Java uses integer division and gets 2 (the .5 is already lost here).

Step 2 — store into the double. The value 2 is placed into result, and as a double it becomes 2.0.

The trap: the type of the variable on the left does not change how the math on the right is done. The .5 was already dropped in Step 1.

result
2.0
Statement 2System.out.println(result);

This prints the content of result, which is 2.0.

❌ double r = 5 / 2;

int math first → 2, then stored → 2.0

✅ double r = 5.0 / 2;

decimal math → 2.5, then stored → 2.5
✅ The answer: 2.0
The right side is computed as int / int = 2, and only afterwards widened to a double → 2.0.

Q6
Primitive Data Types
When + means "add" and when it means "join text"
System.out.println(1 + 2 + "3"); System.out.println("1" + 2 + 3);

The key rule: Java reads + left to right, one step at a time. Between two numbers, + adds. But if either side is a String (text in quotes), + glues text together (this is called concatenation). Let us read each statement step by step.

Statement 1System.out.println(1 + 2 + "3");

Step 1: 1 + 2 — both are numbers → add → 3.

Step 2: 3 + "3" — now one side is text → glue → "33".

1 + 2 + "3" → 3 + "3" → "33"
Statement 2System.out.println("1" + 2 + 3);

Step 1: "1" + 2 — starts with text → glue → "12".

Step 2: "12" + 3 — still text → glue → "123".

"1" + 2 + 3 → "12" + 3 → "123"
✅ The answer: 33 and 123
Same symbols, different order — because the moment a String appears, every following + becomes text-joining.
💡 Remember
Reading order matters. Use parentheses when you mean math: "Sum = " + (1 + 2) prints Sum = 3, not Sum = 12.

Declaration, creation and initialization of an array
int[] marks = new int[3]; System.out.println(marks[0]);

Let us read this program one statement at a time. The first statement quietly does three jobs — declaration, creation, and initialization — so we will draw each one.

Statement 1int[] marks = new int[3];

1) Declaration. int[] marks makes a variable called marks. This kind of variable is a reference: it is meant to hold the location of an array, not the numbers themselves. Before any array is built, it holds null — nothing:

marks
null
only int[] marks has run so far — the variable exists, but no array has been created, so it points to nothing.

2) Creation. new int[3] asks Java to build a real array of 3 integers in memory. 3) Initialization. When an array is created this way, Java automatically fills every slot with the default value, which for int is 0.

Java then puts the reference of that created array into marks. So now marks points to the array:

marks
● reference
the array (created by new)
[0]0
[1]0
[2]0
Statement 2System.out.println(marks[0]);

This follows the reference in marks to the array, and reads the value at index [0], which is the default 0.

✅ Who actually creates the array and its reference?

The operating system does not hand out an address for each array. The OS gives Java one big block of memory when the program launches. After that, the Java Virtual Machine (JVM) itself decides where each new array goes and produces its reference. You never see or choose the real address — the JVM manages it. And when no variable points to an array any more, the JVM's garbage collector frees that memory automatically.

✅ The answer: 0
A newly created int array is initialized with 0 in every slot, so marks[0] is 0.

Default value inside a String array
String[] names = new String[2]; System.out.println(names[0]);

Let us read this program one statement at a time. The key idea: a String is not a primitive — it is an object, so each slot holds a reference, not text directly.

Statement 1String[] names = new String[2];

new String[2] creates an array of 2 slots. Each slot is meant to hold the reference of a String object — but we have not created any Strings yet. So Java initializes every slot to the default for objects, which is null ("points to nothing yet"). This is not an empty text "" — it is "no reference at all".

names
● reference
the created array
[0]null
[1]null
Statement 2System.out.println(names[0]);

This reads slot [0], which holds null, so it prints null.

✅ The answer: null
Object slots default to null — meaning "points to nothing yet", not an empty string.
⚠️ Danger ahead
Calling a method on a null slot — e.g. names[0].length() — would crash the program with a NullPointerException, because there is no object there to run the method on.

int[] a = new int[] { 1, 2, 3 }; int[] b = new int[] { 1, 2, 3 }; System.out.println(a == b);

Let us read this program one statement at a time.

● reference
first array
[0]1

An array lives in memory as long as at least one variable holds its reference. Asking the length of "nothing" → NullPointerException
int[] a = new int[] { 1, 2, 3 }; a = null; System.out.println(a.length);

Let us read this program one statement at a time.

null means "no reference". This erases the reference inside a, so a now points to nothing at all:

Editing the shared array (line 1) persists; reassigning the parameters (lines 2 and 3) never reaches the caller.
🎓 The one idea to carry into tomorrow's lecture

A primitive variable holds the value → passing it makes an independent copy.
An array variable holds a reference → passing it shares the same array.
You can change a shared array's contents from inside a method, but reassigning the parameter itself never affects the caller's variable.
