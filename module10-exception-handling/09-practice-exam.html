Q2 Short Answers — Why and How We Handle Exceptions EASY CLO 13SO-a 6 marks · 1 each

(a) Name the three types of programming errors. Which one does exception handling deal with?

(b) When a runtime error happens, exception handling serves two goals. Name them.

(c) Oracle lists three advantages of exceptions over error codes. Name them.

(d) What is the difference between throw and throws? Give a one-line example of each.

(e) In the division problem, the method int quotient(int a, int b) must not return -1 and must not call System.exit(1) when b is 0. Give one reason for each.

(f) Why should your program not try to catch an OutOfMemoryError?

Model Answer — Q2

(a) Syntax (compile-time) errors, logical errors, runtime errors. Exception handling deals with runtime errors.

(b) Graceful termination (stop safely: save data, close files, roll back) and continued execution (handle the problem and keep running).

(c) Separating error-handling code from regular code · propagating errors up the call stack · grouping and differentiating error types.

(d) throw is a statement in the method body that throws an exception object: throw new ArithmeticException("Divisor cannot be zero"); · throws is written in the method header to declare what it may throw: public void read() throws IOException.

(e) -1 can be a correct answer (e.g. -4 / 4), so the caller cannot tell an error from a result. · System.exit takes the decision away from the caller; the caller should decide whether to stop or ask for new input.

(f) OutOfMemoryError is an Error: a serious JVM/system failure that the program cannot fix (like an earthquake). Only Exceptions are recoverable.

1 mark each; (a), (c) and (e) need all parts for the full mark (½ for partly correct).

Model Answer — Q11

(a) Not having enough money is an external, recoverable situation (the user can choose a smaller amount), so the compiler should force every caller to handle it → checked. A zero or negative amount is a programming/input-checking bug that the caller should have prevented → unchecked.

public class Wallet {
    private double balance;

    public Wallet(double balance) {
        this.balance = balance;
    }

    public double getBalance() {
        return balance;
    }

    public void withdraw(double amount) throws InsufficientFundsException {
        if (amount <= 0)
            throw new IllegalArgumentException("Amount must be positive");
        if (amount > balance)
            throw new InsufficientFundsException(amount - balance);
        balance -= amount;
    }
}
import java.util.*;

public class WalletApp {
    public static void main(String[] args) {
        Scanner input = new Scanner(System.in);
        Wallet w = new Wallet(500);
        System.out.println("Balance: " + w.getBalance());
        boolean done = false;
        while (!done) {
            System.out.print("Amount (0 to stop): ");
            try {
                double amount = input.nextDouble();
                if (amount == 0) {
                    done = true;
                } else {
                    w.withdraw(amount);
                    System.out.println("Withdrawn. Balance: " + w.getBalance());
                }
            } catch (InputMismatchException e) {
                System.out.println("Please enter a number.");
                input.nextLine();                 // discard the bad input
            } catch (InsufficientFundsException e) {
                System.out.println(e.getMessage());
            } catch (IllegalArgumentException e) {
                System.out.println(e.getMessage());
            }
        }
        System.out.println("Goodbye. Final balance: " + w.getBalance());
    }
}

(b) throws InsufficientFundsException in the header (1), the two checks with throw new … in the right order (1), subtract only when valid (1). (c) loop until 0 (1); InputMismatchException caught and the bad token discarded with nextLine() — otherwise the loop never ends (1); both other exceptions caught and their messages printed (1); final line (1).
