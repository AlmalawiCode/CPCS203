1 Animals Make Sounds — A Subclass Is a Specialization

The lecture starts with a family of animals. Animal is the superclass; Dog, Cat and Rooster are subclasses. Every animal has a sound() method — but each subclass makes its own sound.

classDiagram direction TB class Animal { +sound() void } class Dog { +sound() void } class Cat { +sound() void } class Rooster { +sound() void } Animal <|-- Dog : extends Animal <|-- Cat : extends Animal <|-- Rooster : extends
🔑 Two facts about inheritance (lecture slide 7)
  • The inheritance relationship enables a subclass to inherit features from its superclass with additional new features.
  • A subclass is a specialization of its superclass; every instance of a subclass is also an instance of its superclass, but not vice versa.
Every Dog is an Animal ✓  —  but not every Animal is a Dog (it could be a Cat or a Rooster) ✗.
📄 Animal.java and its subclasses▼
class Animal { public void sound() { System.out.println("Some generic animal sound"); } } class Dog extends Animal { @Override public void sound() { System.out.println("Dog says: Woof!"); } } class Cat extends Animal { @Override public void sound() { System.out.println("Cat says: Meow!"); } } class Rooster extends Animal { @Override public void sound() { System.out.println("Rooster says: Cock-a-doodle-doo!"); } } class Duck extends Animal { // used on slides 10–11 @Override public void sound() { System.out.println("Duck says: Quack!"); } }

2 The Golden Condition for Polymorphism

Polymorphism does not work with just any combination of objects. There is one non-negotiable condition:

🔑 The Golden Rule
To treat objects of different types as the same type,
they MUST be related through Inheritance (the IS-A relationship).
✓ Valid — IS-A Relationship Exists
Shape s = new Circle();
// Circle IS-A Shape ✓
Shape s = new Rectangle();
// Rectangle IS-A Shape ✓
Shape s = new Triangle();
// Triangle IS-A Shape ✓
✗ Invalid — No Inheritance Relationship
Shape s = new Student();
// Student is NOT a Shape ✗
Shape s = new Car();
// Car is NOT a Shape ✗
Shape s = new Book();
// Book is NOT a Shape ✗
💡 Why the IS-A Relationship?
If Circle extends Shape, then every Circle object is also a Shape object — it inherits all of Shape's behaviors. This is why we can safely treat a Circle as a Shape. A Student doesn't inherit from Shape, so it doesn't share Shape's behaviors — treating it as a Shape would make no sense.

4 Declared Type and Actual Type

Every reference variable now has two types we must keep apart:

📚 Definitions (lecture slide 9)
  • A variable must be declared a type. The type used in the declaration is the variable's declared type.
    Object o = new GeometricObject();  →  o's declared type is Object.
  • A variable of a reference type can hold a null value or a reference to an instance of the declared type (or of any of its subtypes).
  • The actual type of the variable is the actual class for the object referenced by the variable.
    Object o = new GeometricObject();  →  o's actual type is GeometricObject.
📝 Declared type
Object o = new GeometricObject();
Written on the left. Fixed at compile time. Decides which methods you may call.
📦 Actual type
Object o = new GeometricObject();
Created with new on the right. Known at run time. Decides which version of a method runs.
📄 DeclaredActualDemo.java▼
class GeometricObject { @Override public String toString() { return "I am a GeometricObject"; } } public class DeclaredActualDemo { public static void main(String[] args) { Object o = new GeometricObject(); // declared: Object, actual: GeometricObject System.out.println(o.toString()); // the ACTUAL type decides Object nothing = null; // a reference may also hold null System.out.println(nothing == null); } }
Output — DeclaredActualDemo.java
I am a GeometricObject true
💡 Notice
The variable is declared as Object, yet the text printed comes from GeometricObject's toString() — because the actual object is a GeometricObject. The next section turns this into a rule.

5 Polymorphic References — The Actual Type Decides

🔗 References and Inheritance (lecture slide 10)
An object reference can refer to an object of its own class, or to an object of any class related to it by inheritance.

A polymorphic reference is a variable that can refer to different types of objects at different points in time.
📄 AnimalDemo.java — one reference, many objects (uses the classes from section 1)▼
public class AnimalDemo { public static void main(String[] args) { Animal animal = new Cat(); // declared type: Animal, actual type: Cat animal.sound(); animal = new Duck(); // same reference, now a Duck animal.sound(); animal = new Dog(); animal.sound(); animal = new Rooster(); animal.sound(); } }
Output — AnimalDemo.java
Cat says: Meow! Duck says: Quack! Dog says: Woof! Rooster says: Cock-a-doodle-doo!
⭐ The Rule (lecture slide 11)
It is the type of the object being referenced (the actual type), not the reference type (the declared type), that determines which method is invoked.

The method invoked through a polymorphic reference can change from one invocation to the next: the same line animal.sound(); printed a cat's sound the first time and a duck's sound the second time.
👉 Coming up
How the JVM finds the right method at run time is called dynamic binding — it is explained step by step in Lesson 3 — Dynamic Binding.

6 What Can a Polymorphic Reference See?

This is crucial. When you hold an object through a polymorphic reference (like Shape s), you can only see the methods defined in the superclass. The subclass-specific methods are hidden.

🔍 What does this reference see?
Shape s = new Circle(5.0);
✓ getArea() ✓ getColor() ✓ toString() ✗ getDiameter() ✗ Circle-only methods
Accessible — defined in Shape (superclass)
Inaccessible — defined only in Circle (subclass)
📄 Polymorphic scope example▼
Shape s = new Circle(5.0); s.getArea(); // ✅ OK — getArea() is declared in Shape s.getColor(); // ✅ OK — getColor() is declared in Shape s.toString(); // ✅ OK — toString() is declared in Shape s.getDiameter(); // ❌ COMPILE ERROR! getDiameter() is only in Circle
💡 Think of it as a Filter
A polymorphic reference acts like a "Shape filter". When you look through a Shape filter, you can only see what every Shape knows how to do — the shared, general behaviors. The specific Circle abilities are hidden behind the filter.

This is the price of generality: you gain flexibility (one reference for many types), but you lose direct access to subclass-specific methods. To regain access, you need casting — covered in Lesson 5 — Casting & instanceof.

7 The Coffee Cup Analogy

Let's make these concepts completely clear with a real-life analogy that everyone can relate to!

🔄 The Polymorphic Cup
A general cup — can hold any hot drink!
Cappuccino Latte Tea Hot Choc. Arabic Coffee
Many types ✓
🚫 The Non-Polymorphic Cup
The Arabic coffee cup (فنجان) — only for Arabic coffee!
Arabic Coffee only
Cannot hold cappuccino, latte, or tea — wrong cup!
💡 Making the Connection to Code
  • General Cup = Polymorphic variable HotDrink cup — can hold any subtype
  • Arabic Coffee Cup = Non-polymorphic variable ArabianCoffee cup — holds one specific type only
  • The general cup is more flexible (polymorphic) — works with many drinks
  • The Arabic coffee cup is more specific (non-polymorphic) — works with one drink
📄 The cup analogy in Java code▼
// ☕ Polymorphic cup — any HotDrink works! HotDrink cup; // ← polymorphic variable (the general cup) cup = new Cappuccino(); // ✅ Cappuccino IS-A HotDrink cup = new Latte(); // ✅ Latte IS-A HotDrink cup = new Tea(); // ✅ Tea IS-A HotDrink cup = new ArabianCoffee(); // ✅ ArabianCoffee IS-A HotDrink // 🚫 Non-polymorphic cup — only ArabianCoffee! ArabianCoffee arabicCup; arabicCup = new ArabianCoffee(); // ✅ OK // arabicCup = new Latte(); // ❌ ERROR — Latte is not ArabianCoffee!

8 Polymorphic Call — Passing a Subclass Object to a Superclass Parameter

📞 Polymorphic call (lecture slide 12)
  • The inheritance relationship enables a subclass to inherit features from its superclass with additional new features.
  • A subclass is a specialization of its superclass; every instance of a subclass is also an instance of its superclass, but not vice versa.
  • For example, every circle is a geometric object, but not every geometric object is a circle.
  • Therefore, you can always pass an instance of a subclass to a parameter of its superclass type.

The textbook program PolymorphismDemo (slides 13–14) has a method displayObject(Shape object). Its parameter is of the superclass type Shape, so we can call it with a Circle and with a Rectangle:

📄 Shape, Circle and Rectangle (supporting classes)▼
import java.util.Date; class Shape { private String color; private boolean filled; private Date dateCreated; public Shape(String color, boolean filled) { this.color = color; this.filled = filled; dateCreated = new Date(); // the moment the object is created } public String getColor() { return color; } public boolean isFilled() { return filled; } public Date getDateCreated() { return dateCreated; } } class Circle extends Shape { private double radius; public Circle(double radius, String color, boolean filled) { super(color, filled); this.radius = radius; } } class Rectangle extends Shape { private double width, height; public Rectangle(double width, double height, String color, boolean filled) { super(color, filled); this.width = width; this.height = height; } }
📄 PolymorphismDemo.java (lecture slides 13–14)▼
public class PolymorphismDemo { /** Main method */ public static void main(String[] args) { // Display circle and rectangle properties displayObject(new Circle(1, "red", false)); // a Circle IS-A Shape displayObject(new Rectangle(1, 1, "black", true)); // a Rectangle IS-A Shape } /** Display geometric object properties */ public static void displayObject(Shape object) { // ← superclass-type parameter System.out.println("Created on " + object.getDateCreated() + ". Color is " + object.getColor()); } }
Output — PolymorphismDemo.java (the date is the moment you run it)
Created on Sun Nov 08 01:01:08 AST 2026. Color is red Created on Sun Nov 08 01:01:08 AST 2026. Color is black

The slide shows Created on Mon Mar 09 19:25:20 EDT 2011. Color is red / ... Color is black — the same output, just run on a different day in a different time zone.

🔑 Key idea (slides 13–14)
An object of a subclass can be used wherever its superclass object is used. The call displayObject(new Circle(1, "red", false)) is a polymorphic call: the parameter object has declared type Shape but actual type Circle (first call) and Rectangle (second call).

9 Think! — Which run() Is Invoked?

🤔Question (lecture slide 15)

Suppose the Mammal class has a method called run, and the Horse class (a subclass of Mammal) overrides it. Now consider the following invocation:

📄 The invocation▼
Mammal animal = new Horse(); animal.run();

Which run version will be invoked?

The Horse version.
The declared type of animal is Mammal, but the actual object is a Horse. It is the type of the object (actual type), not the type of the reference (declared type), that determines which method is invoked. Because Horse overrides run(), Horse.run() runs.
📄 MammalDemo.java — try it▼
class Mammal { public void run() { System.out.println("Mammal is running"); } } class Horse extends Mammal { @Override public void run() { System.out.println("Horse is galloping"); } } public class MammalDemo { public static void main(String[] args) { Mammal animal = new Horse(); animal.run(); // prints: Horse is galloping } }
Output
Horse is galloping

10 A Method That Accepts Any Object — Person, Student, GraduateStudent

The most general supertype in Java is Object — every class extends it. So a method whose parameter is of type Object can be called with any object.

classDiagram direction TB class Object { +toString() String } class Person { +toString() String } class Student { +toString() String } class GraduateStudent Object <|-- Person : extends Person <|-- Student : extends Student <|-- GraduateStudent : extends
📄 PolymorphismDemo.java (lecture slides 16–18)▼
class Person { public String toString() { return "Person"; } } //**************************** class Student extends Person { public String toString() { return "Student"; } } //**************************** class GraduateStudent extends Student { } public class PolymorphismDemo { public static void main(String[] args) { m(new GraduateStudent()); m(new Student()); m(new Person()); m(new Object()); } public static void m(Object x) { System.out.println(x.toString()); } }
🔑 Lecture slides 16–17
Method m takes a parameter of the Object type. You can invoke it with any object. Each call is like an assignment to the parameter x:
Object x = new GraduateStudent();
Object x = new Student();
Object x = new Person();
Object x = new Object();
The declared type of x is always Object, but its actual type is different in each call. This feature is known as polymorphism.
🤔Question — What does this program print? (Hint: GraduateStudent has no toString() of its own.)
Output
Student Student Person java.lang.Object@7852e922
  • m(new GraduateStudent()) → Student: GraduateStudent does not override toString(), so it inherits the version from its superclass Student.
  • m(new Student()) → Student: Student's own toString().
  • m(new Person()) → Person: Person's own toString().
  • m(new Object()) → Object's default toString(): the class name, @, and a hexadecimal hash code. The part after @ (here 7852e922) can be different on your computer.

11 Generic Programming

📚 Definition (lecture slide 18)
Polymorphism allows methods to be used generically for a wide range of object arguments. This is known as generic programming.

Look again at the method from the previous section:

📄 One method, a wide range of arguments▼
public static void m(Object x) { // written ONCE System.out.println(x.toString()); } m(new GraduateStudent()); // works m(new Student()); // works m(new Person()); // works m(new Object()); // works — and so would any other object
💡 How it works
  • If the parameter type is a superclass (such as Object or Shape), you can pass an object of any of its subclasses.
  • When the method calls x.toString(), the version that runs is chosen by the actual type of the object — so one generic method gives the right result for every type.
  • We never have to write m(Person), m(Student), m(GraduateStudent) … separately.

12 Complete Code Example

Let's put everything together into a complete, working implementation:

◯ Shape.java — Superclass▼
class Shape { private String color; public Shape(String color) { this.color = color; } public String getColor() { return color; } public String getType() { return "Shape"; } public double getArea() { return 0.0; } @Override public String toString() { return String.format("[%s | %s | area=%.2f]", getType(), color, getArea()); } }
◯ Circle.java  |  ▭ Rectangle.java  |  △ Triangle.java — Subclasses▼
class Circle extends Shape { private double radius; public Circle(String c, double r) { super(c); radius = r; } @Override public String getType() { return "Circle"; } @Override public double getArea() { return Math.PI * radius * radius; } // Circle-specific — NOT accessible via Shape reference! public double getDiameter() { return 2 * radius; } } class Rectangle extends Shape { private double width, height; public Rectangle(String c, double w, double h) { super(c); width = w; height = h; } @Override public String getType() { return "Rectangle"; } @Override public double getArea() { return width * height; } public double getWidth() { return width; } } class Triangle extends Shape { private double base, height; public Triangle(String c, double b, double h) { super(c); base = b; height = h; } @Override public String getType() { return "Triangle"; } @Override public double getArea() { return 0.5 * base * height; } }
📄 PolymorphismDemo.java — The Main Class▼
import java.util.ArrayList; public class PolymorphismDemo { // ✅ ONE polymorphic method — accepts any Shape! public static void printInfo(Shape s) { System.out.println(s); // calls s.toString() — dynamic binding! } public static void main(String[] args) { // ✅ Polymorphic ArrayList ArrayList<Shape> shapes = new ArrayList<>(); shapes.add(new Circle("Red", 5.0)); shapes.add(new Rectangle("Blue", 4.0, 6.0)); shapes.add(new Triangle("Green", 3.0, 4.0)); shapes.add(new Circle("Purple", 2.5)); // ✅ ONE polymorphic loop System.out.println("=== All Shapes ==="); for (Shape s : shapes) printInfo(s); // dynamic binding picks the right getArea() // ── Downcasting demo ────────────────────────────── System.out.println("\n=== Circle-Specific Info ==="); for (Shape s : shapes) { if (s instanceof Circle) { Circle c = (Circle) s; // safe downcast System.out.println("Circle diameter: " + c.getDiameter()); } } } }
Output — PolymorphismDemo.java
=== All Shapes === [Circle | Red | area=78.54] [Rectangle | Blue | area=24.00] [Triangle | Green | area=6.00] [Circle | Purple | area=19.63] === Circle-Specific Info === Circle diameter: 10.0 Circle diameter: 5.0
