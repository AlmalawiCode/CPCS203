Model Answer — Q3

(a) Immutable. Fields are private, there are no mutators, and move returns a new Point instead of changing this one.

(b) Mutable. Rule 2 is broken: increment() is a mutator even though it is not called set….  e.g. c.increment();

(c) Mutable. Rule 3 is broken: getPlayers() returns the real array.  e.g. t.getPlayers()[0] = "X"; — final only stops reassigning the reference, not changing the elements.

(d) Mutable. The getter copies, but the constructor stores the caller’s array. The caller still holds that reference:  int[] a = {90, 80}; Grades gr = new Grades(a); a[0] = 0; → the object changes. Fix: this.g = g.clone();

Model Answer — Q5
public class ImmutablePlaylist {
    private final String name;              // Rule 1: private
    private final int[] durations;

    public ImmutablePlaylist(String name, int[] durations) {
        this.name = name;                   // String is immutable: safe
        this.durations = durations.clone(); // defensive copy IN
    }
    public String getName() { return name; }
    public int[] getDurations() {
        return durations.clone();           // Rule 3: defensive copy OUT
    }
    public int totalSeconds() {
        int sum = 0;
        for (int d : durations) sum += d;
        return sum;
    }
    public ImmutablePlaylist withName(String newName) {
        return new ImmutablePlaylist(newName, durations);   // new object
    }
    // Rule 2: setName and setDuration are removed
}

Rubric: name made private (1) · both setters removed (2) · getter returns a copy (2) · constructor copies the array (1) · withName returns a new object without changing this one (2). final is good practice but on its own earns no mark — a final array can still have its elements changed.

public int levelsToTop() {

public static BigInteger factorial(int n) {
    BigInteger result = BigInteger.ONE;        // or new BigInteger("1")
    for (int i = 2; i <= n; i++)
        result = result.multiply(new BigInteger("" + i));
    return result;
}
