1 The abstract Class — Syntax & Meaning

We agree: it is not logical to create an object of Shape. But programmatically, Java does not automatically prevent it — unless we tell it to. The solution: declare the class as abstract.

abstract class Shape { ... }
❌ Compile Error — Cannot Instantiate
Shape s = new Shape();
// ERROR! Shape is abstract
✅ Correct — Use a Subclass
Shape s = new Circle(...);
// OK! Circle IS-A Shape
🛠 Abstract Class
  • Usually incomplete — normally has one or more methods without a body (it may also have none — see Lesson 4)
  • Cannot be instantiated (new Shape() = error)
  • Must be subclassed
  • Represents a concept too general to be a real object
✅ Concrete Class
  • Complete / fully built — all methods have implementations
  • Can be instantiated (new Circle() = OK)
  • Represents a specific, real-world object
  • A class with no abstract keyword is concrete
📌 Definition — Abstract Class

An abstract class is a class declared with the abstract keyword. It is incomplete — it cannot be instantiated directly. But it can have concrete attributes (like color) and concrete methods (like getColor()) — the "incomplete" part refers only to the abstract methods that have no body yet. Those attributes and concrete methods are fully inherited by every subclass.

📌 Two facts from slides 7–8
  • PhdStudent is said to be a concrete class — it is not abstract, so new PhdStudent() is allowed.
  • You cannot write new Student(), BUT you can still define its constructors, which are invoked in the constructors of its subclasses (through super(...), written by you or inserted automatically by the compiler).
📄 TestStudents.java — complete, runnable version ▼
abstract class Student { protected String login, department, name; public Student() { login = ""; department = ""; name = ""; System.out.println("Student() constructor runs"); } public void setLogin(String login) { this.login = new String(login); } public String getLogin() { return new String(login); } } class PhdStudent extends Student { private String supervisor; public PhdStudent() { super(); // calls the constructor of the abstract class System.out.println("PhdStudent() constructor runs"); } public void setSupervisor(String login) { supervisor = login; } public String getSupervisor() { return supervisor; } } class MscStudent extends Student { } class Undergrad extends Student { } public class TestStudents { public static void main(String[] args) { PhdStudent p = new PhdStudent(); p.setLogin("aalharbi"); p.setSupervisor("almalawi"); System.out.println(p.getLogin() + " is supervised by " + p.getSupervisor()); Student[] all = { p, new MscStudent(), new Undergrad() }; all[1].setLogin("sali"); all[2].setLogin("fomar"); for (Student s : all) System.out.println(s.getClass().getSimpleName() + ": " + s.getLogin()); } }
Output — TestStudents.java
Student() constructor runs PhdStudent() constructor runs aalharbi is supervised by almalawi Student() constructor runs Student() constructor runs PhdStudent: aalharbi MscStudent: sali Undergrad: fomar
❓ Why does Student() run three times?

Every time any subclass object is created, the subclass constructor first calls the superclass constructor. new PhdStudent() calls it through the explicit super(); new MscStudent() and new Undergrad() have no constructor written, so the compiler gives them a default constructor that calls super(). So the constructor of the abstract class runs once for every student object — even though new Student() itself is illegal ("Student is abstract; cannot be instantiated").

3 Constructors of an Abstract Class

The same is true for Shape: the constructors of Shape are invoked in the Circle class and the Rectangle class. An abstract class has constructors so that it can initialise its own fields (here color) for every subclass object.

📄 TestShapeConstructors.java Slide 9 ▼
abstract class Shape { private String color; public Shape() { // constructor of an abstract class this("white"); System.out.println(" Shape() runs"); } public Shape(String color) { // another constructor this.color = color; System.out.println(" Shape(String) runs, color = " + color); } public String getColor() { return color; } public abstract double getArea(); } class Circle extends Shape { private double radius; public Circle() { super(); // invokes Shape() radius = 1; System.out.println(" Circle() runs"); } public Circle(double radius, String color) { super(color); // invokes Shape(String) this.radius = radius; System.out.println(" Circle(double, String) runs"); } public double getArea() { return Math.PI * radius * radius; } } class Rectangle extends Shape { private double width, height; public Rectangle(double width, double height, String color) { super(color); // invokes Shape(String) this.width = width; this.height = height; System.out.println(" Rectangle(double, double, String) runs"); } public double getArea() { return width * height; } } public class TestShapeConstructors { public static void main(String[] args) { System.out.println("new Circle():"); Shape s1 = new Circle(); System.out.println("new Circle(2, \"red\"):"); Shape s2 = new Circle(2, "red"); System.out.println("new Rectangle(3, 4, \"blue\"):"); Shape s3 = new Rectangle(3, 4, "blue"); // Shape s4 = new Shape(); // compile error: Shape is abstract } }
Output — TestShapeConstructors.java
new Circle(): Shape(String) runs, color = white Shape() runs Circle() runs new Circle(2, "red"): Shape(String) runs, color = red Circle(double, String) runs new Rectangle(3, 4, "blue"): Shape(String) runs, color = blue Rectangle(double, double, String) runs
❓ Can you initiate a concrete object from Shape? Why? Slide 9

No. Shape is declared abstract, so new Shape() is a compile error: "Shape is abstract; cannot be instantiated". Shape is too general to be a real object, and it is incomplete (its getArea() has no body — which formula would it use?). Its constructors are not for creating Shape objects; they only run as the first step of building a Circle or Rectangle object (constructor chaining).

4 An Abstract Class as a Data Type

❓ Can I define an array of an abstract class, such as Animal or Shape? Slide 10

YES. An abstract class can be used as a data type — for variables, arrays, parameters and return types. Creating the array does not create any Shape objects; it only creates references (all null at first), and each element can then refer to any concrete subclass object.

The following statement creates an array whose elements are of Shape type:

Shape[] geo = new Shape[10];  ✓ legal — an array of 10 Shape references
geo[0] = new Circle();       ✓ legal — a Circle is a Shape
geo[1] = new Shape();        ✗ illegal — Shape is abstract; cannot be instantiated
📄 TestShapeArray.java ▼
abstract class Shape { public abstract double getArea(); } class Circle extends Shape { private double radius = 1; public double getArea() { return Math.PI * radius * radius; } } class Rectangle extends Shape { private double width = 3, height = 4; public double getArea() { return width * height; } } public class TestShapeArray { public static void main(String[] args) { Shape[] geo = new Shape[10]; // legal: 10 references of type Shape, all null geo[0] = new Circle(); // legal: a Circle is a Shape geo[1] = new Rectangle(); // legal: a Rectangle is a Shape // geo[2] = new Shape(); // compile error: Shape is abstract for (int i = 0; i < 3; i++) { if (geo[i] == null) System.out.println("geo[" + i + "] is null (no object yet)"); else System.out.printf("geo[%d] area = %.2f%n", i, geo[i].getArea()); } } }
Output — TestShapeArray.java
geo[0] area = 3.14 geo[1] area = 12.00 geo[2] is null (no object yet)
javac — if the line geo[2] = new Shape(); is un-commented
TestShapeArray.java:20: error: Shape is abstract; cannot be instantiated geo[2] = new Shape(); // compile error: Shape is abstract ^ 1 error
📌 Remember

new Shape[10] ≠ new Shape(). The first creates an array (legal), the second tries to create a Shape object (illegal). More uses of an abstract type — variables and method parameters — are in Lesson 4, Rule 7.

5 Why getArea() Makes Shape Abstract

Shape {abstract}
 
+getArea(): double
+setColour(int): void
△
extends
Triangle
Circle
Rectangle
Hexagon

Abstract class and abstract method names are written in italics in UML.

  • We cannot create Shape objects, because we cannot provide a reasonable implementation of getArea(). How do we calculate the area of an arbitrary shape?
  • So we declare Shape to be an abstract class.
  • Furthermore, we declare getArea() as an abstract method, because it has no implementation. (setColour(int) can be implemented once for every shape, so it stays a normal method.)
❓ Why have the Shape class in the first place? And why do we have to address getArea() in the Shape class? Slide 11

Why Shape: shared code (e.g. the colour field and setColour() are written once) and a common type for polymorphism (Shape[], Shape s) — see Lesson 1, Section 4.

Why getArea() in Shape: we want to force all shapes to provide an implementation for getArea(). Because it is declared (abstract) in Shape, every concrete subclass — Triangle, Circle, Rectangle, Hexagon — must implement it, and we can call s.getArea() on any Shape reference.
