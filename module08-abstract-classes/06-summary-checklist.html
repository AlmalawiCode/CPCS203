1 Summary — What You Learned in This Module

≠
Abstract ≠ Abstraction
Abstract class is a Java keyword. Abstraction is OOP's 2nd pillar. Different things!
🕐
Abstract Meaning
Abstract = vague, general, incomplete. Cannot represent a specific real-world object.
🖌
The Shape Story
"Draw a shape" — you cannot draw just a shape. It is too general. Same in Java: no new Shape().
🏪
Why Keep Shape?
Inheritance (avoid redundancy) + Polymorphism (IS-A relationship). Both require the superclass.
🛠
abstract keyword
Prevents instantiation. Class and/or method can be abstract. Compiler enforces rules.
📋
Abstract Method
Header only, no body. Forces subclasses to implement. 100% guarantees the behavior exists.
📙
8 Rules (Lesson 4)
All → concrete. Some → still abstract. Has abstract method → must be abstract. Can be data type. And more.
💼
Manager Technique
Make a concrete method abstract in a subclass to force all developers to implement it.
🔢
Number Case Study
java.lang.Number is abstract. Integer, Double, etc. extend it. Use Number as a polymorphic type.
📌 The Complete Definition

An abstract class is a class that is declared with the abstract keyword. It may contain abstract methods (header only, no body) and/or concrete methods. It cannot be instantiated, but it can be used as a data type for polymorphism. Any class that inherits abstract methods must either implement all of them (becoming concrete) or declare itself abstract too.

B. Lesson 2 — The abstract Class Slides 7–11 · open lesson

Prove it — test yourself
Which of these compile? Student s = new PhdStudent(); / Student s = new Student(); / PhdStudent p = new PhdStudent();
Show answer
1st: yes (a PhdStudent is a Student). 2nd: no — "Student is abstract; cannot be instantiated". 3rd: yes — PhdStudent is a concrete class.
Review in the tutorial: Lesson 2, §2 →
Prove it — test yourself
If nobody can call new Student(), who calls Student's constructor?
Show answer
The constructors of its subclasses — through super(...), written explicitly or inserted by the compiler. It runs once for every subclass object created (e.g. Shape's constructors are invoked in Circle and Rectangle).
Review in the tutorial: Lesson 2, §2–3 →
Prove it — test yourself
Can you write new Shape() when Shape is abstract? Why?
Show answer
No — compile error "Shape is abstract; cannot be instantiated". Shape is too general and incomplete (e.g. getArea() has no body). Its constructors exist only to initialise the Shape part of subclass objects.
Review in the tutorial: Lesson 2, §3 →
Prove it — test yourself
Mark each line legal or illegal: Shape[] geo = new Shape[10]; / geo[0] = new Circle(); / geo[1] = new Shape();
Show answer
legal √ (an array of 10 Shape references, all null) / legal √ (a Circle is a Shape) / illegal X (Shape is abstract).
Review in the tutorial: Lesson 2, §4 →
Prove it — test yourself
Why can we not create Shape objects, and why must getArea() still appear in Shape?
Show answer
We cannot give a reasonable implementation of getArea() for an arbitrary shape, so getArea() is an abstract method and Shape an abstract class. It is declared in Shape because we want to force all shapes to provide an implementation of getArea() (and so we can call it through a Shape reference).

public abstract void draw(int size); — the body is missing (semicolon instead of { }). Such a method is an abstract method (just as Person p; declares an object without creating it).

If Circle did not implement getArea(), what would you have to do? And what does the slide's (radius^2)*PI really compute?

Circle would have to be declared abstract too (otherwise: "Circle is not abstract and does not override abstract method getArea() in Shape"). ^ is XOR in Java: 5^2 = 7, so the area is 7 × 3.1419 = 21.9933 — use radius * radius * Math.PI.

D. Lesson 4 — The Rules of Abstract Classes Slides 17–21 · open lesson

Prove it — test yourself
Is abstract class Animal { public void eat() { } } legal? Can you write new Animal()?
Show answer
Legal — it simply cannot be instantiated with new; it is used as a base class for defining new subclasses.
Review in the tutorial: Lesson 4, Rule 5 →
Prove it — test yourself
A subclass can be abstract even if its superclass is concrete. Example?
Show answer
Object is concrete, but its subclass Shape (or GeometricObject) is abstract.
Review in the tutorial: Lesson 4, Rule 6 →
Prove it — test yourself
Shape has no draw(); Star and Circle do. Shape someShape = new Star(); someShape.draw(); — which line is wrong and why?
Show answer
Line 1 is legal (a Star is a Shape). Line 2 is a compile error: some Shape might not have a draw() method — a class knows its superclass, but not its subclasses.
Review in the tutorial: Lesson 4, §2 →
Prove it — test yourself
With abstract class Shape { public abstract void draw(); }: are new Star(), new Shape() and someShape.draw() legal? What access must Star's draw() have?
Show answer
Shape someShape = new Star(); legal; new Shape() no longer legal; someShape.draw() legal — every actual instance must have draw(). Star's draw() must be public ("attempting to assign weaker access privileges; was public" otherwise).
Review in the tutorial: Lesson 4, §2 →
Prove it — test yourself
GeometricObject s = new GeometricObject(); / GeometricObject s = new Circle(4); / double area = s.getArea(); / Circle c = new Circle(3); / c.setColour(GREEN); / area = c.getArea();
Show answer
Only the first is illegal (GeometricObject is abstract); the other five are legal. (In Liang's code the setter is spelled setColor(String).)
Review in the tutorial: Lesson 4, §3 →
Prove it — test yourself
Animal re-declares Object's toString() as public abstract String toString();. What must Animal be, and why would anyone do this?
Show answer
Animal must be declared abstract. It is rare, but useful when the superclass implementation becomes invalid in the subclass — it forces every concrete subclass to write its own toString().
Review in the tutorial: Lesson 4, §4 →
Prove it — test yourself
How can a manager make the compiler force every class to implement toString()?
Show answer
Create abstract class BaseEntity that overrides toString() as abstract; every class extends BaseEntity, so a class without toString() does not compile.

E. Lesson 5 — Case Study: the Abstract Number Class Slides 22–23 · open lesson

Prove it — test yourself
Is new Number() legal? Name four subclasses and the four abstract methods of Number.
Show answer
No — Number is abstract. Subclasses: Integer, Double, Float, Long, Short, Byte, BigInteger, BigDecimal. Abstract methods: intValue(), longValue(), floatValue(), doubleValue() (byteValue and shortValue are concrete).
Review in the tutorial: Lesson 5, §1 →
Prove it — test yourself
Why do list.add(45) and list.add(3445.53) both compile for ArrayList<Number> list?
Show answer
Autoboxing turns 45 into an Integer and 3445.53 into a Double; both are subclasses of Number, so both fit a list of the abstract type Number.
Review in the tutorial: Lesson 5, §2 →
Prove it — test yourself
What does LargestNumbers print for 45, 3445.53, 33.9, 46? Why compare with doubleValue()? What is returned for an empty list?
Show answer
"The largest number is 3445.53". doubleValue() is an abstract method every Number must implement, so it works for any element (< does not work on objects). For null or an empty list the method returns null.
Review in the tutorial: Lesson 5, §2 →
