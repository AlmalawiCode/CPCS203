(a) Circles, rectangles and triangles all have a colour, a filled flag and a creation date. Name the two benefits we gain by moving these into one superclass.

Model Answer — Q2

(a) Avoiding redundancy (the shared code is written once) and software reuse (we build on a class that is already designed, implemented and tested).

Model Answer — Q6

(a) 10.0 / 10.0 — overriding (same signature; the int 10 is widened to double and A’s version runs both times).

class Base {
    public static void fun() {
        System.out.println("Base fun");
    }
    public void show() {
        System.out.println("Base show");

    }

    }

    }
}
public class Main {

        Base.fun();
        Derived.fun();
        Derived d = new Derived();
        d.show();
        System.out.println(d);
    }
}

(a) Write the exact output. (4 marks)

(b) Is Derived.fun() overriding Base.fun()? Explain in one sentence. (1 mark)

(c) Why does System.out.println(d) call toString() even though we never wrote d.toString()? (1 mark)

Model Answer — Q8
Base fun
Derived fun
Base show
Derived show

(b) No — it hides it. Static methods are inherited but cannot be overridden; a redefined static method hides the superclass one, which is still reached with Base.fun().

Model Answer — Q10
public class Rectangle extends Shape {
    private double width;
    private double height;

    public Rectangle() {
        this(1.0, 1.0, "white", false);     // reuse the other constructor
    }
    public Rectangle(double width, double height,
                     String color, boolean filled) {
        super(color, filled);               // first statement
        this.width = width;
        this.height = height;
    }
    public double getArea() {
        return width * height;
    }
    public double getPerimeter() {
        return 2 * (width + height);
    }
    @Override
    public String toString() {
        return super.toString() + ", width: " + width
                                + ", height: " + height;
    }
}

// new Rectangle(4, 2.5, "red", true) prints:
// color: red, filled: true, width: 4.0, height: 2.5

Rubric: extends Shape + private fields (1) · no-arg constructor using this(…) (1) · super(color, filled) as the first statement (2) · getArea and getPerimeter (1) · toString overridden with @Override and super.toString() (3). Writing this.color = color loses the constructor marks: color is private in Shape.

Model Answer — Q11

(a) Vehicle holds -plate, -year, +getAge(currentYear). Car (-seats), Truck (-loadCapacity) and Motorcycle (-hasSidecar) each keep only their own field, with a hollow triangle arrow pointing up to Vehicle.

public class Vehicle {
    private String plate;
    private int year;

    public Vehicle(String plate, int year) {
        this.plate = plate;
        this.year = year;
    }
    public String getPlate() { return plate; }
    public int getYear()     { return year; }
    public int getAge(int currentYear) {
        return currentYear - year;
    }
    @Override
    public String toString() {
        return plate + " (" + year + ")";
    }
}

public class Truck extends Vehicle {
    private double loadCapacity;

    public Truck(String plate, int year, double loadCapacity) {
        super(plate, year);
        this.loadCapacity = loadCapacity;
    }
    public double getLoadCapacity() { return loadCapacity; }
    @Override
    public String toString() {
        return "Truck " + super.toString()
               + ", load " + loadCapacity + " t";
    }
}

(c) No. A garage is not a vehicle; it has vehicles. That is aggregation (a Vehicle[] field), not inheritance — inheritance must pass the is-a test.
