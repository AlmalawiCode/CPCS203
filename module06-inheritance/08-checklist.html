A. What Inheritance Is — and Why We Use It

Prove it — test yourself
Complete: “Inheritance allows a developer to ______ a new class from an ______ one. The child inherits the ______ and ______ of the parent.”
Show answer
…to derive a new class from an existing one. The child inherits the methods and data (fields) of the parent — every accessible member, but never the constructors.
Review in the tutorial: Lesson 2, §3 →
Prove it — test yourself
In class Circle extends Shape, give three names for Shape and four names for Circle.
Show answer
Shape: parent class, superclass, base class. Circle: child class, subclass, derived class, extended class.
Review in the tutorial: Lesson 2, §3 →
Prove it — test yourself
Circles, rectangles and triangles share colour, filled and date of creation. (1) What is the best design to avoid redundancy? (2) Why is reuse “a fundamental benefit”?
Show answer
(1) Put the common features in one superclass Shape and let the three classes extend it. (2) We capitalise on all the effort that went into the design, implementation and testing of the existing class.
Review in the tutorial: Lesson 1, §3 →
Prove it — test yourself
Which arrow shows inheritance in UML, and which way does it point? Is “Car extends Engine” proper inheritance?
Show answer
A hollow triangular arrow pointing to the superclass. No — a car has an engine, it is not an engine. Proper inheritance is an is-a relationship: the child is a more specific version of the parent.
Review in the tutorial: Lesson 2, §1 →
Prove it — test yourself
Name the four “child’s features”.
Show answer
1. Inherit the superclass members  2. Add new properties (fields)  3. Add new methods  4. Override (modify) inherited methods.
Review in the tutorial: Lesson 2, §5 →
Prove it — test yourself
Shape has color and filled; Circle extends Shape and adds radius. How many fields does a Circle object have?
Show answer
Three (color, filled, radius). A subclass is a specialisation — it has everything the parent has plus its own additions, so it is never “smaller”.
Review in the tutorial: Lesson 2, §4 →
Prove it — test yourself
Inside Circle(double radius, String color, boolean filled), is this.color = color; legal? If not, give two legal alternatives.
Show answer
Illegal — color is private in Shape. Alternatives: call the inherited public setters setColor(color); setFilled(filled);, or call super(color, filled); as the first statement. (Making the field protected also works.)

B. Constructors and the Keyword super

Prove it — test yourself
Write one line that calls a superclass constructor and one line that calls a superclass method.
Show answer
super(color, filled); (constructor — first statement only) and super.toString() (method — anywhere in the method).
Review in the tutorial: Lesson 3, §1 →
Prove it — test yourself
Shape has a public constructor Shape(String, boolean). Can you write new Circle("Red", true) if Circle defines no such constructor?
Show answer
No. Constructors are not inherited. They can only be invoked from a subclass constructor with super(...). A child’s constructor is responsible for calling the parent’s.
Review in the tutorial: Lesson 3, §1 →
Prove it — test yourself
Rewrite public A(double d) { x = d; } the way the compiler sees it. What does Java do for a class with no constructor?
Show answer
public A(double d) { super(); x = d; } — if neither this(...) nor super(...) is written, the compiler puts super() first. A class with no constructor gets a default A() { super(); }.
Review in the tutorial: Lesson 3, §1 →
Prove it — test yourself 
public class Apple extends Fruit { }

class Fruit {
    public Fruit(String name) {
        System.out.println("Fruit's constructor is invoked");
    }
}
Does it compile?
Show answer
No. Apple’s default constructor calls super(), but Fruit has only Fruit(String) — no no-arg constructor. Fix: add Fruit() or give Apple a constructor that calls super("Apple").
Review in the tutorial: Lesson 3, §1 (Quick Check + Challenge 15) →
Prove it — test yourself
Which of these constructor bodies compile? (a) { Shape("Red"); } (b) { print(); super(); } (c) { super(); this(1); } (d) { this(1); print(); }
Show answer
Only (d). (a) calling the superclass constructor by its name is a syntax error; (b) super() must be the first statement; (c) super and this cannot both appear.
Review in the tutorial: Lesson 3, §1 (CAUTION + Cheat Sheet) →
Prove it — test yourself 
public class Faculty extends Employee {
    public static void main(String[] args) { new Faculty(); }
    public Faculty() { System.out.println("(4) Faculty"); }
}
class Employee extends Person {
    public Employee() { this("(2) Employee(String)"); System.out.println("(3) Employee()"); }
    public Employee(String s) { System.out.println(s); }
}
class Person {
    public Person() { System.out.println("(1) Person"); }
}
What is printed?
Show answer
(1) Person → (2) Employee(String) → (3) Employee() → (4) Faculty. Constructing an object invokes all the superclasses’ constructors along the inheritance chain, deepest ancestor first.
Review in the tutorial: Lesson 3, §2 →
Prove it — test yourself 
class A { public A(int x) { } }
class B extends A { public B() { } }
public class C {
    public static void main(String[] args) { B b = new B(); }
}
What problem arises when compiling?
Show answer
B() implicitly calls super(), but A has no no-arg constructor → compile error. (If A had A() printing a message, new B() would print it.)

C. Overriding Methods

Prove it — test yourself
What must be identical for a subclass method to override a superclass method? Why write @Override?
Show answer
The name, parameter list (signature) and return type (a subtype return is allowed). @Override makes the compiler report an error if you did not really override.
Review in the tutorial: Lesson 4, §3 →
Prove it — test yourself
Circle overrides toString(). Write a version that keeps Shape’s text and adds the radius. Is super. needed before getDateCreated()?
Show answer
return super.toString() + "\nradius is " + radius;. For getDateCreated(), super. is optional — Circle does not override it, so there is only one version.
Review in the tutorial: Lesson 4, §6 →
Prove it — test yourself
Base has public void fun(); Derived declares private void fun(). Output of new Derived().fun() in Derived’s main? And if Base’s fun() were private instead?
Show answer
First case: compile error — weaker access privileges. Second case (Base private): the methods are unrelated, no overriding; it prints Derived fun.
Review in the tutorial: Lesson 4, §3 →
Prove it — test yourself
Person has getInfo() returning "Person" and printPerson() printing getInfo(). Student overrides getInfo() → "Student". Output of new Person().printPerson(); new Student().printPerson();? And if both getInfo() methods were private?
Show answer
Overridden: Person, Student. Private: Person, Person (private methods are not overridden).
Review in the tutorial: Lesson 4, §6 (challenges) →
Prove it — test yourself 
class A {
    int i = 7;
    public A() { setI(20); System.out.println("i from A is " + i); }
    public void setI(int i) { this.i = 2 * i; }
}
class B extends A {
    public B() { System.out.println("i from B is " + i); }
    public void setI(int i) { this.i = 3 * i; }
}
// main: new A(); new B();
What is printed?
Show answer
i from A is 40, i from A is 60, i from B is 60. During new B(), A’s constructor runs first, but setI is B’s overriding version (3 × 20).
Review in the tutorial: Lesson 4, §6 (challenges) →
Prove it — test yourself
Parent: public Object getValue(). Child: public String getValue(). Legal? And the reverse (parent returns String, child returns Object)?
Show answer
First: legal (String is a subtype of Object — covariant return). Reverse: compile error.
Review in the tutorial: Lesson 4, §5 (challenges) →
Prove it — test yourself 
class Base { public static void fun() { System.out.println("Base fun"); } }
class Derived extends Base {
    Derived() { super.fun(); }
    public static void fun() { System.out.println("Derived fun"); }
    public static void main(String[] args) {
        Derived obj = new Derived();
        obj.fun();
        Base.fun();
    }
}
What is printed? How do you call the hidden method?
Show answer
Base fun, Derived fun, Base fun. A redefined static method hides the superclass one; call the hidden one with SuperClassName.staticMethodName() — e.g. Base.fun().

D. Overriding vs. Overloading

Prove it — test yourself
Where can each one happen, and what must be the same / different?
Show answer
Overriding: different classes related by inheritance; same signature and return type. Overloading: same class or classes related by inheritance; same name, different parameter list.
Review in the tutorial: Lesson 4, §5 →
Prove it — test yourself
B has p(double i) printing i*2. A extends B. Calls: a.p(10); a.p(10.0);. Output if A defines (a) p(double i) printing i; (b) p(int i) printing i?
Show answer
(a) Overriding → 10.0 10.0. (b) Overloading → 10 20.0.
Review in the tutorial: Lesson 4, §5 →
Prove it — test yourself
A has set(String) printing “Hello A”. B extends A with set(int) printing “Hello B”. Output of b.set(8) and b.set("A")? What if B’s method is set(String)?
Show answer
b.set(8) → Hello B, b.set("A") → Hello A (both overloading). With set(String) in B → Hello B (overriding). Same idea for m(int)/m(String): B inherits m(int) and overloads it.

E. Visibility — protected and Accessibility

Prove it — test yourself
Who can access a protected member of a public class? Order: public, private, protected, default.
Show answer
Any class in the same package, and subclasses even in a different package. Order: private → default → protected → public.
Review in the tutorial: Lesson 5, §1 →
Prove it — test yourself
C1 (package p1) has public x; protected y; int z; private u; protected m(). C4 extends C1 in package p2; C5 is in p2 and not a subclass. Which can each access?
Show answer
C4: x, y, m() — not z, not u. C5: only o.x. (Same-package classes C2/C3 can use x, y, z, m — never u.)
Review in the tutorial: Lesson 5, §1 →
Prove it — test yourself
Shape has protected void Print(). Circle overrides it as (a) private void Print(); (b) public void Print(). Which compiles?
Show answer
(a) Error — weaker access. (b) Correct — protected → public is allowed.

F. The final Modifier

Prove it — test yourself
What happens with: final static double PI = 3.14159; then PI = 3; — class B extends A where A is final — B overriding A’s final void m1()?
Show answer
All three are compile errors: a final variable is a constant; a final class cannot be extended (e.g. Math, String); a final method cannot be overridden.

G. The Object Class and toString()

Prove it — test yourself
What is the superclass of public class Circle { }?
Show answer
java.lang.Object — class Circle is the same as class Circle extends Object.
Review in the tutorial: Lesson 5, §3 →
Prove it — test yourself
System.out.println(loan); prints Loan@15037e5. What are the three parts? Is println(loan) the same as println(loan.toString())?
Show answer
Class name + @ + a number for the object in hexadecimal. Yes, they are equivalent. The default is not helpful, so we override toString() to return a digestible description.

H. Multiple Inheritance

Prove it — test yourself
Can class PickupTruck extends Car, Truck compile? Why does Java forbid it, and what gives us “aspects of multiple inheritance”?
Show answer
No. A Java class has exactly one parent. Multiple parents cause collisions (e.g. the same variable or method name in both parents) that must be resolved. Interfaces give aspects of multiple inheritance without the overhead.
